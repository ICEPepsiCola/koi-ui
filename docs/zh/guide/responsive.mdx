# 响应式原理

## 断点

| 断点 | 宽度 |
|------|------|
| sm | 640px |
| md | 768px |
| lg | 1024px（默认桌面 / 移动分界） |
| xl | 1280px |
| 2xl | 1536px |

## 组件侧行为

大部分反馈 / 表单 / 数据组件支持 `responsive`：

- 默认 `true`：按视口在桌面布局与移动布局间自动切换
- `false`：始终使用桌面布局（便于嵌入已有移动壳或固定样式）

```text
<Table responsive={false} columns={cols} data={data} />
<Modal responsive={false} open={open} onClose={close}>...</Modal>
```

文档预览里的「桌面端 / 移动端」开关会注入 `previewDevice`，便于在同一页面对照两端效果。

## SSR

服务端默认按桌面渲染，客户端 hydrate 后按真实视口切换。若落地页以移动为主，可用：

```text
<KoiProvider ssrMode="mobile">...</KoiProvider>
```

## 平板与「中间态」

默认在 **lg（1024px）** 一切换桌面 / 移动形态。平板常落在中间：

- **偏后台、要表格密度** → 关键组件或全局用 `responsive={false}`，保持桌面布局，自行处理窄屏滚动。
- **偏 App / H5** → 保持默认自适应，或把 `KoiProvider` 的 `breakpoint` 调到 `md`，更早进入移动形态。
- **同一页混用** → 列表可用移动卡片，编辑弹层用 `Modal responsive={false}` 锁桌面。

Koi 不做第三套「平板专用」布局，避免再维护一套组件树；用断点与 `responsive` 表达意图即可。

## 密度

控件密度主要通过 `size`（如 Input / Select 的 `sm` | `md`）与布局间距控制，没有全局 `density` token。后台页优先 `sm` + 紧凑 `Space`/`Stack`；移动页保持默认 `md` 触控热区。
